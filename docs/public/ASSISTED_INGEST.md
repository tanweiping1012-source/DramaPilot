# 把本地视频和人工资料导入源资产包

短剧文件本身没有结构化的“谁在说话、哪段是冲突、哪件道具重要”。本阶段让创作者提供已有剧本、字幕和人工标注，程序核对文件及位置，再保存为后续改编可以引用的源资产包。

这是 **assisted ingest（人工辅助导入）**。程序读取实际文件、计算hash、探测视频时长和帧数、解析SRT；人物身份、镜头动作和故事含义来自输入的标注。没有运行语音识别或视觉模型，也没有把这些标注验证为剧情事实。

本模块使用独立导入清单 `0.1.0`，输出已有 `0.3.0-draft.1` 源资产契约；旧DSH工具的 `0.2.1` 契约不变。首次支持MP4/MOV视频、UTF-8剧本文本和SRT。它不是上传网页、自动识片或目标视频生成器。

## 先看一个完整的自编例子

需要Node.js 24.x、FFmpeg和ffprobe。工具和字体的设置见[本地运行](RUNNING.md)。用未使用过的输出目录运行：

```bash
npm ci --ignore-scripts
npm run fixture:media -- .runtime/color-fixture
npm run demo:ingest -- .runtime/color-fixture/fixture-only.mp4 .runtime/my-source-demo
```

命令会打印审阅HTML、源资产JSON和导入记录的位置。打开审阅HTML，查看三段源镜头、对应的文字证据、字幕时间和未知项。视频只有水印色块与测试音；故事、两个人物和台词都是自编文本，画面没有演出这个故事。字幕存在也不表示视频已包含中文或英语配音。

例子中“家族权力关系”保留为推断和待复核项。程序检查的是引用与文件位置，不会把它提升为已识别的人物关系。

## 自己准备资料时怎样做

先阅读样例运行目录的 `input-manifest.json`。它分成四部分：

| 部分 | 填什么 | 谁提供或检查 |
|---|---|---|
| `source_package` | 包ID、版本、源语言 | 创作者选择；当前只创建新快照 |
| `assets` | 本地文件路径、类型和来源；SRT明确对应哪个视频 | 程序读取文件，测量hash/时长/帧数/文本长度 |
| `annotations` | 源人物、关系、对白、场景、道具、故事节拍、镜头和证据位置 | 人工提供；程序检查范围、引用和来源分类 |
| `preparation` | 人工准备资料花费的时间及说明 | 用户声明值，与程序导入耗时分开；不知道可留空 |

文件路径须是工作区内的相对路径，不接受URL、绝对路径、`.`/`..`路径段或符号链接。命令使用本地文件，不上传到服务商。不要把目标国家的新对白或新人物写入源资料；目标创作属于后续步骤。

```bash
npm run ingest:source -- path/to/input-manifest.json . .runtime/my-source-import
```

第二个参数是工作区根目录，第三个参数是新的输出目录。为防止把旧证据覆盖成新结果，已存在的输出目录会被拒绝。导入失败或取消会移除本次创建的未完成目录；导入成功后的文件设为只读并保留hash，但这不是防篡改存储。

人物与场景并不会从SRT自动推断。SRT只提供字幕正文及时间；源对白的说话人需要人工标注和对应证据。不确定的人物关系应明确记为 `inferred` 并填写未知项；近似重建记为 `reconstructed`，两者不能显示为已确认观察。

## 程序接口与当前限制

`dramapilot/assisted-ingest` 导出 `importAssistedSource({manifest, workspaceRoot, outputDir, tools?, signal?})`、`AssistedSourceManifestSchema` 与 `parseSrt`。成功返回源包、导入记录和三个文件路径：`source-package.json`、`receipt.json`、`review.html`；媒体/文本副本在 `assets/` 中，报告只引用本地副本。

每批最多16个资产，单个文本2 MiB、单个视频2 GiB、合计4 GiB，清单4 MiB。当前视频需恰有一个可探测视频流和有效时长；MOV外部数据引用禁用。SRT采用从1开始的连续编号与标准毫秒时间戳；保留重叠字幕并提示审阅，不自动合并或分配说话人。不能保证所有编码/平台兼容。

## 导入成功意味着什么

- 本地文件可读取，保存的快照有确切hash；视频参数来自实际ffprobe。
- 剧本和字幕保留原文。文字定位使用JavaScript的UTF-16下标，不能直接把UTF-8字节位置当字符位置；BOM、换行和表情符号也会影响下标。
- 字幕时间不越过所绑定视频的实际时长，镜头和证据的位置不越界，所引用人物/场景/对白确实存在于输入包。
- 报告保留素材来源、标注方法、观察/推断/重建类别，以及未解决事项；这些信息不会被“文件校验成功”替代。

文件存在和引用正确，不证明字幕转写准确、角色身份识别正确、场景匹配或素材已获发布许可。它也不提供收费生成或平台发布权限。

## 与后续步骤怎样连接

这一步只生成源资产。DP-N3将持久保存独立目标分镜并映射制作请求；DP-N4才渲染本地2D预演；DP-N5处理可信制作确认与依赖失效。当前不会因为导入成功自动提交任何生成任务。

新代码随仓库最新源码提供；旧 `v0.2.0-engineering.1` Release 下载包不包含本模块。实际已运行的检查与未验证项见[验证记录](VALIDATION.md)，任务状态见[路线图](ROADMAP.md)。
