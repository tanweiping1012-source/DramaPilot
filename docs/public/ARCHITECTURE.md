# 新链路架构增量（设计提案）

更新于2026-09-17。方案v0.3，**当前运行契约仍为0.2.1**。完整链路仍是设计方案；其中DP-N1已有独立`0.3.0-draft.1`实验契约与元数据校验，实际API及限制见[WORKFLOW_DRAFT](WORKFLOW_DRAFT.md)。它未接入旧DSH工具，不赋予执行权限。DSH固定0.1.5-rc.2 / fb2c4b9e698e30edb738bca4cf0618587db7d203。

## 已有实现与差距

| 已有模块 | 可以继续使用 | 新链路缺口 |
|---|---|---|
| contracts / adaptation | StoryBible、LocaleBible、CharacterBible、AdaptationMap、引用版本与不可变保存 | 新draft已表达源证据、场景/道具、独立目标分镜和制作包元数据；持久导入与执行仍待接入 |
| ingest | 工作区内本地文件路径约束与hash | 尚无自动视频理解、对白转写、镜头解析或人物关联 |
| orchestration / providers | SQLite任务、预算预留、语义请求去重、模拟故障与六方法provider | 分阶段状态与制作包确认；真实供应商未接入 |
| media | 本地probe/hash、帧时间线、字幕、显式音轨合成与取消 | 动作提取、白模重建、预演编辑及白模作为生成控制 |
| review / dsh | HTML审阅、11个实际工具、真实DSH协议调用 | 源目标资产对照、阶段操作、创作者确认与发布确认 |

现有ShotPlan使用源shot_id，校验要求plan对应源Shot；它不能直接表达目标版拆镜、合镜或新增反应镜头。新架构必须显式迁移，而不是给源镜头偷偷改名。

## 拟议数据对象

| 对象 | 主要内容 | 关键规则 |
|---|---|---|
| SourceEvidence | source asset/hash、时间段/帧、观察内容、产生方式、不确定项 | 区分observed/inferred/reconstructed；它与fixture/mock/live/external_manual的执行证据分类是两个维度 |
| SourceAssetPackage | 源剧本、人物关系、角色/场景/道具参考、源分镜与证据 | 摄像机没拍到的信息不能变成确定事实；创作者补充需记录来源 |
| SourceStoryboard | 源镜头ID、原时间段、人物/动作/对白与证据 | 保留原片顺序与范围；修正生成新revision |
| SceneBible / PropAsset | 场景/道具ID、source或target角色、参考文件hash、空间与文化约束 | 场景和道具变更只传播到实际引用它们的资产 |
| TargetStoryboard | 独立目标镜头ID、顺序、来源映射、动作、对白、时长、路线 | 允许一对多、多对一及有理由的新增镜头；不能捏造源区间 |
| PrevisArtifact | source/target用途、2D/2.5D/3D方式、动作/相机/深度可用项、媒体与时间线、输入引用、不确定项 | 记录imported/manual/reconstructed/fixture；跳过写原因；原片和目标预演不互相覆盖 |
| TargetProductionPackage | 目标剧本、人物/场景/道具、分镜、必要白模、声音和路线的确切引用 | 形成内容hash与版本快照；引用的预演必须对应同一剧本/动作版本 |
| ExecutionConfirmation | 前置阶段绑定其输入/计划hash；正式制作绑定完整制作包hash；同时记录素材范围、阶段/供应商、额度与修复范围 | 由可信主机/用户动作记录；授权只覆盖绑定阶段，不从模型输出approved推导 |
| ReleaseConfirmation | 成片hash、质量未验证项的明确处置、发布目的地与范围 | 导出与平台发布分开；成片变化使旧确认失效 |

字段命名、存储与版本号要在契约任务中评审后冻结。不得直接扩大0.2.1的严格schema并继续宣称同一契约兼容。

## 迁移方式

1. 保留现有0.2.1固定样例、账本与已发布包的读取行为。
2. 先以独立draft schema和样例评审新增对象，明确未来版本号与升级规则。
3. 0.2.1导入只生成能依据现有字段成立的映射；缺失的源证据、场景、白模或发布确认保留unknown/not_available，不能伪造。
4. 目标镜头映射与依赖规则通过后，再迁移请求构建、缓存、校验和合成覆盖检查。
5. 历史账本保持原请求身份；迁移和重启不得引起重新提交或丢失未知费用预留。

## 执行和制作的分层

DSH负责任务运行、模型与工具调度；DramaPilot维护业务资产、版本、批准与依赖；视觉/声音供应商按结构化参数执行；媒体模块校验和合成。

正式批量制作前确认目标制作包。若理解、参考图或预演阶段也有外部调用，须提前确认该阶段的素材范围和额度，再在完整制作包确认时汇总既有支出与剩余额度。制作包尚未形成时，前置授权绑定该阶段的输入与计划hash；它不能放行正式视频制作。正式制作授权另绑定完整制作包hash。模型提案不直接触发上传或收费。

逐目标镜头选择edit/regenerate/reuse。真实供应商适配继续遵循capabilities/quote/submit/poll/cancel/collect，未知能力写unknown。白模能否输入、保留什么运动和构图，是供应商能力及样例验证结果，不能统一假设。

## 阶段状态与修复

拟议业务阶段分别保存not_started/in_progress/needs_review/confirmed/failed/skipped等状态；这些阶段状态不替换已有生成任务状态，也不代表质量通过。每次确认绑定输入和输出hash；输入改变后仅撤销受影响的确认和下游产物有效性。

修复按问题层级返回：理解错误回源证据；文化/剧情错误回改编；动作/时长错误回目标分镜和预演；生成伪影回对应镜头；字幕/混音错误回合成。始终保留源资产和历史候选。

## 首个实现边界

先完成无收费辅助导入、结构化源目标资产、本地二维预演、明确的制作包确认和mock全链路。自动逆向三维、真实视觉/配音、目标受众效果是独立后续验证。白模只是输出MP4而没有来源、时序、版本和可检查动作，不能视为该阶段完成。
