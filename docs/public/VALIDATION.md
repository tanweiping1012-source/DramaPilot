## 发布包验证

公开快照在全新目录 `npm ci`、测试和默认 Demo 通过；Linux GitHub Actions 的离线检查通过。独立脚本在公开快照复跑，15 项与 6 组结果均通过。

## 独立恢复测试覆盖什么

- 供应商 submit 被调用之前，另一 SQLite 连接已能读到持久化预留。
- 远端接受后丢失回执；保留 7 单位预留，总额 10 时新增 4 单位被拒绝。
- 远端接受后强制结束本地进程；重启和更换 operation ID 都不重复提交同一语义请求。
- 轮询超时后使用原 job ID 继续查询。
- 两个进程竞争同一操作，模拟远端只接受一次；两个各 6 单位的操作竞争总额 10，只允许一个。
- 远端不支持取消时，不伪造 cancelled，也不自动退回预留。

模拟远端的计数与应用账本分别存储，防止仅检查应用自己的“成功”字段。真实供应商的网络/幂等/计费行为仍需后续验证。

## 质量没有被验证

源视频自动理解、角色视觉一致性、实际英语声音、口型、文化自然度、叙事质量、观众接受度均未验证。测试片含水印与测试音；报告中的技术通过只表示对应文件/引用检查，不代表这些质量项通过。

模型自主规划、DSH 对话会话持久化、真实供应商接入、整集处理、跨平台媒体兼容性也不在当前结论内。

## 已知功能限制

台词变更后的解耦视频可被标为复用候选，但合成对旧台词依赖仍保守拒绝；没有完整的重新审阅后复用流程。无关镜头保留历史改编版本作为来源记录，与复用已改变台词的镜头是不同情形。

```bash
npm ci --ignore-scripts

```

媒体与 DSH 命令见 [RUNNING.md](RUNNING.md)。独立验收使用新输出目录，命令如下。commit 参数用于绑定固定代码版本；新draft驱动还检查生产代码与该提交一致，验收结果由正反例断言决定。

```bash
node tests/acceptance/workflow-draft.mjs . .runtime/independent-workflow "$(git rev-parse HEAD)"
node tests/acceptance/episode-revisions.mjs . .runtime/independent-episode "$(git rev-parse HEAD)"
node tests/acceptance/recovery.mjs . .runtime/independent-recovery "$(git rev-parse HEAD)"
```
